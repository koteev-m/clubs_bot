## 3. Что реально открывается на `/app`

### 3.1. Canonical packaged surface

`/app` и `/app/` по умолчанию остаются `AS_BUILT` статической витриной «Куда пойдём?». Отдельно, `/app?mode=support` — `AS_BUILT` bounded React entry для staff list/detail/thread/take/reply/resolve/close, а `/app?mode=guest-support` — `AS_BUILT` bounded React entry для own-ticket guest list/detail/thread/continuation. Ни один mode не делает React role shell canonical surface:

- `app-bot/src/main/kotlin/com/example/bot/routes/WebAppRoutes.kt:16-49`, `webAppRoutes`, отвечает legacy `webapp/app/index.html` на `/app` и `/app/`, а вложенный compiled React index выбирает только для exact `mode=support` или `mode=guest-support`; `/app/react/index.html` не раздаётся, а публикуются только его assets;

### 3.2. Bounded served React support modes and remaining React source

The bounded React modes are `AS_BUILT` only for their separately served support surfaces:

- `/app?mode=support` → nested tracked React index → `miniapp/src/app/App.tsx:15-53` → `SupportShell`; `/app?mode=guest-support` reaches the same nested index and then `GuestSupportShell`. Both wait until authenticated initData is installed before their first request. Query `mode` selects presentation only and never supplies identity, role, permission or club authority;
- `miniapp/src/modules/support/api/support.api.ts:1-230` has secured permitted-club/list/detail GETs plus `/assign`, `/reply`, `/resolve` and `/close`; `SupportShell.tsx:81-750` renders a permitted-club selector, optional status filter, list, minimal detail, complete thread, loading/empty/error/forbidden states, back navigation and server-capability-driven mutations;
- take appears only for a `NEW` ticket with `canTakeInWork`; reply appears only for `NEW`/`IN_PROGRESS` with `canReply` and trims non-blank text to 2,000 characters. Resolve appears only for `IN_PROGRESS` with the server-derived status-management capability and opens separate Confirm/Cancel state before sending `{"confirmed": true}`. Close appears only for `RESOLVED` with that capability and has no body. Mutations block duplicate submission; `403` clears pending/confirmation state and refreshes capabilities; `404` clears the selected thread. `RESOLVED` and `CLOSED` have no reply form; `CLOSED` has no mutation controls. Agent-thread messages render only the public delivery status: `Доставлено`, `Не доставлено`, `Результат доставки не подтверждён`, `Доставка выполняется`, or legacy `Статус доставки не зафиксирован`. Only confirmed `delivered` reply success says «Ответ доставлен»; failed, unconfirmed and generic delivery persistence errors refresh the thread/list and do not claim success. There is no reopen control, generic status selector, retry control or permission-management UI;
- `miniapp/src/modules/guest/pages/GuestSupportShell.tsx:1-465` presents only the authenticated guest's list, bounded load/empty/error/retry/refresh states, back/detail refresh, complete ordered thread and guest-facing sender labels. It permits a non-blank continuation of at most 2,000 characters only for `NEW`, `IN_PROGRESS` and `RESOLVED`, blocks duplicate submit, and authoritatively reloads both detail and list after success. `RESOLVED` reloads as `IN_PROGRESS`; `CLOSED`, legacy and unsupported states have no composer. `403` clears the guest surface, `404` clears the selected ticket, and request IDs isolate stale and cross-ticket responses;
- `miniapp/src/modules/guest/api/support.api.ts` uses validated initData with server-side identity and owner-scoped guest APIs; it exposes no application/Telegram/agent IDs, internal delivery ID, failure code, audit fingerprint, raw response, initData or token. The supplied backend preserves no-store headers, detail-free public errors and foreign/missing non-enumeration;
- `WebAppRoutes.kt:40-48` exposes React assets only beneath `/app/react/assets`; direct React index and `mode=admin`/other non-support attempts do not expose a new canonical role shell.

The remaining React role surfaces are `PRESENT_UNWIRED` relative to canonical `/app`:

- `miniapp/src/app/App.tsx:17-53`, `App`, still contains `admin`, `promoter`, `entry`, `my-nights` and `guest` source branches; only the bounded `support` and `guest-support` branches are served by `WebAppRoutes`;
