# Факты / Оценки / Гипотезы

## Факты (Telegram платформа)

- Telegram Bot API **10.0** добавил **Guest Mode** (бот может получать “guest\_message” и **отвечать в чатах, где он не состоит**, через `answerGuestQuery`). ([Telegram](https://core.telegram.org/bots/api "Telegram Bot API"))
- В **Guest Mode** бот получает **только контекст “сообщение‑вызов + сообщение‑reply”**, **не имеет доступа к истории чата и списку участников**; по одному вызову — **один ответ**; можно упомянуть **до 3 гостевых ботов**. ([Telegram](https://core.telegram.org/bots/features "Telegram Bot Features"))
- В Bot API есть `sendMessageDraft` для **стриминга черновика** (временный превью‑драфт на \~30 секунд), затем нужно отправить финальное сообщение `sendMessage`. ([Telegram](https://core.telegram.org/bots/api "Telegram Bot API"))
- В Bot API есть **Paid Broadcasts**: по умолчанию 30 msg/s; можно включить повышенный лимит до 1000 msg/s, а сообщения сверх бесплатных 30 msg/s стоят Stars (0.1 Stars/сообщение) и требуют минимальный баланс Stars. ([Telegram](https://core.telegram.org/bots/api "Telegram Bot API"))
- Telegram описывает **bot‑to‑bot communication** и прямо требует **защиту от бесконечных циклов** (dedup, rate limit, depth/timeouts). ([Telegram](https://core.telegram.org/bots/features "Telegram Bot Features"))
- В Telegram Business есть **connected bots**, которые могут отвечать на сообщения “от имени” бизнес‑аккаунта. ([Telegram](https://core.telegram.org/api/business "Business"))
- Официальный Bot API upload‑лимит и Local Bot API upload‑лимит отличаются (Local поддерживает существенно больший upload, до \~2000MB в таблице). ([Telegram](https://core.telegram.org/bots/features "Telegram Bot Features"))

## Оценки (как это влияет на продукт)

- Guest Mode — лучший UX‑буст: iBota можно вызывать **в рабочем чате смены** или **в групповом чате гостей** без добавления бота в чат (но с ограничением: отвечаем безопасно, без PII).
- `sendMessageDraft` делает AI‑ответы “живыми”, но **все критические подтверждения** (бронь, финансы, списания бонусов) должны фиксироваться **финальным сообщением** и/или кнопкой подтверждения.

## Гипотезы (что даст максимальный эффект)

- “AI‑форма вместо ручной формы” (iBota превращает текст в заполненную форму и просит подтвердить) снизит время операций у промо/host/менеджера в 2–4 раза.
- “AI‑сводка ночи/сети по запросу” повысит управляемость и дисциплину внесения данных.

# 0) Что это за приложение и зачем оно нужно

**Telegram Club OS** — это единая система в Telegram (бот + mini‑app), которая заменяет разрозненные процессы клуба:

- бронирование столов по интерактивной схеме,
- гостевые списки промоутеров,
- check‑in входа,
- управление столами в течение ночи (депозиты/доплаты/услуги/освобождение),
- финансовое закрытие смены (люди/браслеты/выручка по статьям),
- геймификация и лояльность (штампы ночей, ранний приход, бейджи, розыгрыши),
- музыка от DJ (файлами) и интерактивы,
- коммуникации и рассылки,
- статистика по клубу и по сети,
- безопасность/аудит/анти‑фрод,
- аварийные режимы на случай сбоев.

## Главное изменение v2.0

Мы добавляем **iBota** — **AI‑ассистента**, который работает для всех ролей:

1. **Внутри бота и mini‑app** как “Помощник”.
2. **В любом чате** (группы/лички/рабочие) через **Guest Mode**: пользователь пишет `@нашбот …`, iBota отвечает прямо там. ([Telegram](https://core.telegram.org/bots/features "Telegram Bot Features"))
3. Может “думать вслух” через **стриминг черновика** (`sendMessageDraft`), но финальные действия — только подтверждением. ([Telegram](https://core.telegram.org/bots/api "Telegram Bot API"))

# 1) Блок 1. Роли и права доступа (RBAC) + iBota

## 1.1. Роли

- **Гость**
- **Промоутер (глобальный)**
- **Host / Менеджер входа**
- **Менеджер зала**
- **Менеджер клуба**
- **Админ клуба**
- **Финансовый менеджер клуба**
- **DJ**
- **Владелец (Owner)**
- (опционально) **Главный админ**, **Главный менеджер сети**

## 1.2. Scope доступа

- **GLOBAL** — сеть (все клубы)
- **CLUB** — конкретный клуб

## 1.3. Принцип iBota: “помогает всем, но делает только то, что разрешено”

iBota всегда:

- **определяет роль пользователя**,
- проверяет **scope** (какой клуб ему доступен),
- и показывает только те действия/данные, которые человек имеет право видеть.

### Пример

Менеджер зала пишет в рабочем чате:
`@нашбот сколько свободных VIP столов сейчас?`
iBota:

- проверяет, что это менеджер зала этого клуба,
- отвечает: “Свободно: 6 столов. Топ‑3 по вместимости: …”
  Если доступа нет — ответ: “Нет прав. Откройте mini‑app ‘Столы’”.

## 1.4. Критические операции всегда требуют подтверждения

Даже если iBota “понял” запрос:

- **бронь**, **отмена**, **посадка**, **депозит**, **доплата**, **закрытие смены**, **корректировки**
  — только через кнопку **“Подтвердить”** (в боте или mini‑app).

# 2) Блок 2. Календарь клуба и доступность + iBota

## 2.1. Что такое “операционная ночь”

Операционная ночь — это реальный интервал работы клуба. Он может:

- начинаться в 00:00 “пятницы” и длиться до 12:00 “субботы”,
- при этом в календаре это всё равно “ночь пятницы”.

## 2.2. Настройки календаря (по умолчанию)

- Рабочие дни недели (обычно пт/сб, иногда вс)
- Время работы (старт/конец)
- **Cut‑off бронирований**: “закрыть бронь за 2 часа до конца ночи” (настраиваемо)
- Исключения (не работаем)
- Дополнительные ночи (праздники)
- TZ клуба

## 2.3. iBota в календаре (для всех ролей)

### Для гостя

- “Сегодня работает MIX?” → iBota отвечает + даёт кнопку “Открыть карту столов”.
- “Когда ближайшая ночь?” → iBota покажет ближайшие рабочие ночи.

### Для владельца/менеджера

- “Добавь дополнительную ночь 22→23 февраля” → iBota открывает мастер “Добавить ночь” с заполненными полями и просит подтвердить.
- “Смести ранний приход с 03:00 на 02:00” → iBota показывает предупреждение (повлияет на геймификацию и логику) и просит подтверждение.

### Уведомления

При изменениях календаря:

- гостям (кто подписан и/или кто имеет бронь на изменённую ночь),
- промоутерам (у кого списки),
- управленцам (в рабочий контур).

# 4) Блок 4. Бронирование столов (гость) + iBota

## 4.1. Основной поток (как было) — теперь “с AI‑ускорением”

1. Гость выбирает клуб/ночь
2. Открывает схему зала (mini‑app)
3. Нажимает на стол → создаётся **HOLD**
4. Указывает кол‑во гостей
5. Видит депозит (расчёт)
6. Контакты: ник авто, телефон опционально
7. Подтверждает правила
8. Подтверждает бронь
9. Получает подтверждение + Night Pass QR

**Инварианты:**

- нельзя 2 HOLD одновременно,
- бронь держится 30 минут после времени прихода,
- менеджер может продлить удержание,
- отмена возможна до последнего момента,
- за 2 часа до конца ночи новые брони недоступны.

## 4.2. iBota в бронировании

iBota умеет:

- принимать свободный текст (“стол на 6 в VIP в субботу к 2”)
  и превращать его в **черновик брони**, который пользователь подтверждает.

### Что iBota НЕ делает сам

- не подтверждает бронь без кнопки,
- не меняет сумму,
- не “держит” стол бесконечно (HOLD TTL — по правилам).

## 5.1. Общая навигация mini‑app

Вверху — кнопка **“iBota”** (Помощник).
Снизу — разделы (для гостя):

- Клубы

- Схема/Столы
- Мои брони
- Пропуск (QR)
- Мои ночи
- Музыка
- Вопросы

Для персонала и управленцев открываются свои разделы по роли.

## 5.2. iBota внутри mini‑app

iBota там работает как:

- “плавающая кнопка” → открывает чат‑панель
- умеет:
  - объяснить экран (“что здесь делать”),
  - заполнить форму из текста,
  - подсказать следующий шаг (“вам осталось подтвердить правила”).

## 5.3. iBota в любом чате (Guest Mode)

Сценарии:

- В гостевом групповом чате: “@нашбот где есть стол на 4 сегодня?”
- В рабочем чате смены: “@нашбот сколько сейчас HOLD и какие столы рисковые?”
  Guest Mode даёт iBota возможность **ответить прямо там**, даже если бот не добавлен в чат. ([Telegram](https://core.telegram.org/bots/features "Telegram Bot Features"))
  Но при этом iBota не видит историю и участников — значит он отвечает строго по вызову и по ролям. ([Telegram](https://core.telegram.org/bots/features "Telegram Bot Features"))

# 6) Блок 6. Вход и гостевые списки промоутеров + iBota

## 6.1. Два варианта гостевых списков (как вы хотите)

### Вариант 1 — “Список ФИО”

Промоутер:

- вставляет список “Имя Фамилия” (много строк) **или** добавляет по одному.
  Host/вход:
- на входе ищет гостя по ФИО (или в списке),
- отмечает “Пришёл”.

Если не отметили — значит не пришёл.

### Вариант 2 — “Приглашение по QR/ссылке”

Промоутер:

- создаёт каждому гостю ссылку/QR приглашение
- гость открывает → попадает в бот → получает Night Pass
  Host:
- сканирует Night Pass → гость отмечается как пришёл.

## 6.2. Один QR для всего (решаем вашу боль “2 QR — геморрой”)

Мы используем **Night Pass** как **единственный** QR на ночь:

- он покрывает:
  - check‑in,
  - ранний приход/штамп,
  - участие в розыгрышах,
  - привязку стола к гостю (если нужно).

Если гость:

- в списке → после скана Night Pass система сама знает: “это гость из списка” и отмечает и список, и посещение.
- со столом → менеджер зала после скана Night Pass привяжет к столу/депозиту (если гость хочет участвовать в лояльности).

## 6.3. Защита от пересылки и повторов

В Night Pass:

- “живой” QR/код,
- повторный скан не создаёт вторую отметку.

## 6.4. iBota в работе промо и входа

### Промоутеру

- “Вот список из заметок, сделай гостевой лист на MIX на субботу”
  iBota:
- чистит формат,
- убирает дубли,
- подсвечивает ошибки,
- создаёт черновик списка,
- просит подтвердить,
- предлагает “сгенерировать приглашения” (внутренние/внешние).

### Host/входу

- “Этот гость говорит, что он в списке, но я не вижу”
  iBota:
- предлагает быстрый поиск,
- подсказывает варианты причины,
- даёт скрипт ответа гостю.

# 7) Блок 7. Операционка столов (менеджер зала/клуба) + iBota

## 7.1. Основные задачи

- видеть свободные/занятые столы
- посадка (депозит / по счёту / от клуба)
- внесение депозита
- доплаты
- отдельная услуга “личная охрана”
- распределение депозита (бар/шары/50‑50/… по настройкам)
- освобождение стола (“гости ушли”)
- no‑show
- стоп продаж столов + Undo

## 7.2. Что меняется с iBota

Менеджер пишет:

- “посади стол 12, депозит 60000, 30000 бар/30000 шары”
  iBota:
- открывает форму “Посадить стол 12” уже заполненную,
- менеджер проверяет и жмёт “Подтвердить”.

Или:

- “гость доплатил 15000 в шары” → iBota готовит “Доплата”.
- “добавь охрану 10000” → iBota готовит “Услуга: охрана”.

## 7.3. Сценарий “клуб закрылся раньше”

По вашему решению:

- “кнопка закрыть ночь” остаётся, но как **операционная блокировка продаж столов**, а не как “открытие смены”.
  То есть:
- **ночь открывается автоматически** по расписанию,
- но менеджер может нажать:
  - “Остановить продажи столов (до конца ночи)”
  - и если ошибся — “Отменить остановку” (Undo).

# 8) Блок 8. Финансовая смена (финансовый менеджер) + iBota

## 8.1. Принцип

- смена открывается автоматически,
- закрывает смену только финансовый менеджер клуба,
- после закрытия данные замораживаются.

## 8.2. Что вводит финансист

1. Люди:

- женщины, мужчины, отказы

2. Браслеты:

- типы настраиваемые (дефолт: бесплатные/платные/стол/VIP/backstage)
- можно добавить “DJ” и т.п.

3. Выручка:

- статьи настраиваемые
- у каждой статьи флаг “в общую выручку / не в общую”
- депозитные карты по умолчанию “не в общую”

4. Сверка со столами:

- система показывает расхождение.

## 8.3. iBota для финансиста

- помогает заполнять (подсказывает “в прошлую субботу было примерно X, проверь”)
- ловит ошибки (“депозитные карты включены в общую — так нельзя”)
- формирует итоговый отчёт “для владельца”.

# 9) Блок 9. Геймификация и лояльность (клубная) + iBota

## 9.1. Что фиксируем

- посещения (штампы) — только после check‑in (один раз за ночь)
- ранний приход — по правилу клуба (настраиваемое время)
- бейджи — за пороги посещений/ранних/активностей
- розыгрыши — включаем/выключаем, задаём период и условия
- лояльность по столам — накопительная, настраиваемая

## 9.2. Как гость это видит

Раздел “Мои ночи”:

- прогресс по штампам
- бейджи (названия на русском)
- активные розыгрыши: “что нужно сделать”
- прогресс по лояльности столов (если включено)

## 9.3. iBota в геймификации

Гость спрашивает:

- “Почему мне не засчитали ранний приход?”
  iBota проверяет:
- был ли check‑in
- время check‑in
- правило раннего прихода этой ночи
  и объясняет.

Владелец/менеджер:

- “Сделай новую лестницу бейджей: 5/15/40, названия такие‑то”
  iBota создаёт черновик конфигурации и просит подтверждение.

# 11) Блок 11. Музыка и DJ‑интерактив (файлы) + iBota

## 11.1. Что нужно DJ

- загрузка треков/сетов **файлами**
- карточка (обложка/описание/теги/клуб/ночь)
- модерация (если включена)
- интерактивы:
  - “главный трек ночи”
  - голосования/реакции
- поддержка DJ (донаты)

## 11.2. Ограничения файлов (важно для ожиданий)

Telegram Bot API имеет ограничения на upload; Telegram официально описывает разницу лимитов между “Official” и “Local Bot API” (Local может быть значительно выше, до \~2000MB). ([Telegram](https://core.telegram.org/bots/features "Telegram Bot Features"))
Продуктово это означает:

- “обычные” треки/сеты — грузим как есть,
- “слишком большой сет” — предлагаем вариант загрузки “как серия частей” или “опубликовать укороченную версию”, либо используем режим с большим лимитом (если включён).

## 11.3. iBota для DJ

- помогает оформлять релиз (название/описание/теги),
- генерирует анонс для канала/рассылки,
- помогает запускать интерактив (“сделай голосование на 15 минут”).

## 12.2. Анти‑спам и лимиты

## 12.3. Массовая отправка

Telegram Bot API по умолчанию — 30 сообщений/сек на бот, и есть механизм Paid Broadcasts для увеличения лимита (с оплатой Stars). ([Telegram](https://core.telegram.org/bots/api "Telegram Bot API"))
Продуктово:

- “обычные” рассылки — медленно и безопасно,
- “важные уведомления” — можно ускорять (если владелец включил платный режим).

## 12.4. iBota для коммуникаций

- предлагает сегменты (“покажи, кому отправим”)
- делает варианты текста
- проверяет, не нарушаем ли частотные лимиты
- даёт предпросмотр: “как выглядит в Telegram”.

# 17) Блок 17. Безопасность, аудит, анти‑фрод + iBota

## 17.1. Guest Mode — удобно, но требует правил

Guest Mode даёт возможность отвечать “в любом чате”, но бот:

- не видит историю и участников,
- получает контекст только вызова,
- отвечает 1 раз на вызов. ([Telegram](https://core.telegram.org/bots/features "Telegram Bot Features"))

**Политика продукта:**

- в публичных/неизвестных чатах iBota отвечает только общими фактами и ссылками, без PII.
- персональные данные и админ‑действия — только в личном чате/mini‑app.

## 17.2. Аудит “опасных” действий

- денежные операции, корректировки, закрытие смены, смена ролей — всегда логируются и требуют причины.

## 17.3. Анти‑фрод промо и персонала

- промо оцениваем по ARRIVED/SEATED, а не “сколько вписал”
- лимиты, флаги по no‑show/denied
- защита от дублей: один приход, один штамп, один бонус.

# 18) Сквозной модуль iBota (AI‑ассистент) — правила работы (обязательный раздел)

Чтобы iBota был “сразу максимально” и при этом не ломал продукт:

## 18.1. Где живёт iBota

1. **Внутри бота** — кнопка “iBota”
2. **В mini‑app** — кнопка “iBota”
3. **В любом чате через Guest Mode** — вызов `@нашбот …` ([Telegram](https://core.telegram.org/bots/features "Telegram Bot Features"))

## 18.2. Как iBota отвечает

- быстрый “черновик” может идти стримом через `sendMessageDraft` (ощущение живости) ([Telegram](https://core.telegram.org/bots/api "Telegram Bot API"))
- финальная операция всегда подтверждается кнопкой/формой.

## 18.3. Что iBota умеет по ролям (короткая таблица)

- **Гость**: подобрать клуб/зону/стол; объяснить правила; помочь оформить вопрос; напомнить про бронь.
- **Промо**: распознать список; создать GuestList; сделать приглашения; подсказать “что улучшить по качеству”.
- **Host/вход**: быстрый поиск; подсказка по причине отказа; анти‑дубль; протокол при сбоях.
- **Менеджер зала**: “что свободно”; посадка/депозит/доплата/охрана через заполненные формы; освобождение столов.
- **Менеджер клуба**: сводка ночи; остановка продаж (и undo); управление конфликтами; контроль промо.
- **Финансист**: подсказки по вводу; проверки аномалий; формирование отчёта.
- **DJ**: оформление релиза; интерактив; посты/анонсы; статистика.
- **Owner/сеть**: аналитика по запросу; добавление клуба “мастером”; контроль рисков и алертов.

## 18.4. Границы iBota (чтобы “без ошибок”)

iBota **не делает**:

- финансовые проводки без подтверждения,
- массовые рассылки без предпросмотра + подтверждения,
- корректировки после закрытия смены без супер‑прав,
- выдачу бонусов “вручную” без основания.

## 18.5. Bot‑to‑bot (опционально)

Если в будущем делаем несколько ботов‑агентов, Telegram требует loop prevention (dedup, rate limit, depth/timeouts). ([Telegram](https://core.telegram.org/bots/features "Telegram Bot Features"))
В v2.0 можно оставить 1 бот (без мульти‑ботов), но заложить правила, чтобы потом расшириться.

## 18.6. Business connected bots (опционально)

Для промоутеров/клубных аккаунтов можно подключать business‑ботов, чтобы отвечать “от имени профиля” (если вы захотите). ([Telegram](https://core.telegram.org/api/business "Business"))
Но это отдельный режим, который включается осознанно (с политикой доступа и шаблонами сообщений).

# 19) Что меняется в концепции после внедрения iBota — коротко

1. **Каждая роль получает “один вход” в любые действия**: текстом → iBota → заполненная форма → подтвердить.
2. **Гостевые списки** становятся проще: копипаст списка и приглашения в 1–2 шага.
3. **Операционка столов** ускоряется: вместо “тыкать 10 экранов” — “сказать и подтвердить”.
4. **Финансы** становятся точнее: iBota ловит типовые ошибки, помогает сверять.
5. **Управление сетью** становится проще: сводки и сравнения “вопросом”.
6. Уникальный UX: **вызов бота в любом чате** без добавления в чат (Guest Mode). ([Telegram](https://core.telegram.org/bots/features "Telegram Bot Features"))
